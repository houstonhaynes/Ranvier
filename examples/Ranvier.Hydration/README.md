# F# server rendering and hydration

Giraffe serves a Ranvier page with a greeting and starting count chosen for each request. The browser hydrates the existing server elements and connects the counter button. Both sides use the same F# component and `Page.Definition`; the server generates the HTML and F# browser entry point.

## Run

From the repository root, restore the local .NET tools with `dotnet tool restore`. Then, with the .NET 10 SDK and Node.js 26 or newer:

```sh
cd examples/Ranvier.Hydration
npm ci
npm run build
npm start
```

Open <http://127.0.0.1:5080/?greeting=Hello%20Ada&start=7>. Change `greeting` and `start`, or disable JavaScript to inspect the useful server-rendered page. Clicking **Add one** changes browser-local state; reloading starts from the request's values again. This example does not persist a counter on the server.

`greeting` defaults to `Hello from F#` and is limited to 200 UTF-16 code units without splitting a surrogate pair. `start` accepts an integer from 0 to 1,000,000 and otherwise defaults to 3.

## Files

- [HydrationPage.fs](HydrationPage.fs) defines the modern Sugar component, request parsing, `Ranvier.Wire` codec, shared page, and `render` function.
- [Server/Program.fs](Server/Program.fs) returns `HydrationPage.render props` through Giraffe's `htmlString` handler and serves the compiled assets.
- [Client.fsproj](Client.fsproj) compiles the entry generated by `Page.clientSource` against the same shared page.
- [vite.config.mjs](vite.config.mjs) bundles that entry as `assets/client.js`, which the live server also references.

`npm run build` first runs the .NET server with `--write-pages`. It generates `index.html` and `generated-pages/Index.fs`, then compiles the F# browser code and bundles the static site into `dist`. Generated HTML, startup code, and build outputs are ignored by Git.

The page's state codec serializes the exact props used for server rendering into a script element. `PageClient.start`, emitted by `Page.clientSource`, decodes those props and hydrates strictly. It does not reconstruct the request state from browser defaults or insert fresh HTML.

The tiny document metadata wrapper uses `Component.define` because the document builder supplies title and meta declarations. The visible counter uses the modern `Component.ofMembers` and Sugar element syntax.

## Static documentation preview

The documentation publishes `dist` at `/Ranvier/examples/hydration/` using its existing GitHub Pages site. Relative asset URLs allow the same output to work in a nested directory. The preview contains the deterministic default greeting and count, with a working hydrated button; GitHub Pages does not run the Giraffe process, so query parameters do not personalize that preview.

Equivalent [Oxpecker and Suave server source](../../docs/content/server/backends.md) reuses this shared page and compiled assets. Those are source examples rather than additional hosted services.

## Verify

```sh
npx playwright install chromium
npm test
```

The full test command builds from source and runs HTTP/browser checks for rendering without JavaScript, retaining server DOM nodes through hydration, interactive state, request isolation, untrusted text encoding, query defaults, routes/assets, and hydration under a nested static URL.
