# Correspondence

Each row maps a symbol of the model to the F# in `src/Ranvier/Core.fs` (pinned at commit
`d701e6c5`), and lists every simplification with its reason.

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `node_id` | node identity | `nat`; node ids are opaque. |

## Reference tier

The reference tier defines meaning for any engine, so it has no Core.fs symbol for marks, freshness
or the queue. Task 12 relates it to the engine. These rows record its fragment and where its
choices come from.

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `val := Z` | generic `'T` | Unbounded integers against Core.fs's fixed-width integers in user bodies. Overflow is outside the tier, so a body whose arithmetic wraps in F# has a different value here. |
| `program` | a graph built by user code | A static node set. A program whose effect creates or disposes nodes is outside the fragment and keeps only the general engine theorems. Author's call, from the plan. |
| `program_memos`, `well_behaved_memo` | `Memo` | No previous-value argument, ownership, cleanups, writes, disposal, effect creation or untracked read. A memo has no comparer here: cutoff compares outcomes by equality, as `CmpEq`. `CmpNever` and `CmpThrows` are outside the fragment. |
| `memos_acyclic` | none | A rank that decreases along every read, for every answer the reads can give. A cycle or self-read that some answers would reach is outside the fragment, whether or not the program's signals reach it. |
| `program_effects`, `well_behaved_effect` | `Effect` | Bodies use `CRet`, `CThrow`, `CLet`, `CIf`, `CRead`, `CTryRead`, `CReadUntracked`, `CWrite`, `CCleanup`, `CLog`, `CBatch`, and no `EPrev`: an effect has no previous value. `well_formed_program` rejects `CSignal`, `CMemo`, `CEffect`, `CDispose`. |
| `exec` on `CIf` | `if` in a body | A zero condition selects the else branch. |
| `exec` on `CTryRead` | `TryValue` | `ok` binds 1 or 0, and `x` binds the value or the failure's identity. |
| `exec` on `CRead` | `Value` | A failed memo ends the body with its failure, and the read counts as tracked. |
| `exec` on `CBatch` | `RunBatch` | Sequences its parts. Writes apply immediately, and a flush cannot nest in a round. |
| `eval_expr` on `EDiv`, `div_zero_failure` | `DivideByZeroException`, `Effect.RunBody` | A zero divisor is the failure `div_zero_failure`, the body's outcome, as `RunBody` records the exception. Later effects run. The identity is one fixed value, so it has the difference in the `Fail f` row: F# throws a new exception per zero divisor, so a memo that fails this way on consecutive recomputes has moved in F# and has not moved here. `CThrow (-1)` denotes the same failure. |
| `Fail f`, `outcome` in read comparison | `Failure.Moved`, `Graph.FailureOf` | `f` denotes an exception instance. Outcomes compare by `f`, as `Moved` compares instances by reference. `CThrow f` is a body throwing the same stored instance on every evaluation, so an unmoved failure wakes nothing. A body throwing a new exception per recompute has no fixed `CThrow` form: `FailureOf` allocates a new `Failure`, the failure has moved and wakes readers, whereas `CThrow 7` on re-evaluation is the same outcome and wakes nothing. Tasks 4 and 12 rely on this row. |
| `EvRun` | `Effect.RunBody`, `runs` | Emitted once per effect run, after its cleanups. Memo-body evaluation is not an event, so the observable number of runs is the number of effect runs. A memo's run count belongs to the engine. |
| `EvLog` in a memo | a user side effect in a memo body | Discarded in this tier: its count would be a memo's run count. |
| `run_cleanups` | `Graph.Discharge`, `Owner.DisposeScope` | Newest first, before the body, with reads untracked. On a re-run, a cleanup registered by a cleanup joins the new scope, as `Owner.AddCleanup` does. A failed cleanup ends only itself and emits `EvFail n f`. In F# it goes through `RecordError` to `Root.Errors` (Core.fs 1085), which names no effect, whereas `EvFail` here carries `n`, so the differential check has no node to compare for these. Whether that failure then escapes the flush is engine behaviour, examined by scenario `S09b`. |
| `run_effect` on a failed body, `EvFail` | `Effect.RunBody`, `FailureOf` | `RunBody` records the failure on the effect's own `failure` field (Core.fs 4871), cleared at the start of each run (4840), and `run_effect` emits `EvFail n f` after the body's events. The next run clears the field, so the differential check has to read a body failure before then. A read of a failed memo fails the reader with the memo's failure. A memo's own failure has no event, since its evaluation count belongs to the engine. Later effects and later rounds run, and the reads and cleanups reached are kept. |
| `RDispose`, `apply_dispose` on an effect, `EvDispose` | `Effect.Dispose`, `Graph.Retire` | Host disposal only: disposal from inside an effect is outside this tier. Applies in batch order, before the batch's settling. Emits the pending cleanups, then `EvDispose`. `Tracer.NodeDispose` fires before the cleanups in F#, and the tracer is outside the model. The effect's entry is removed, so it has no reads and no later round runs it. A cleanup's writes apply, and wake readers in the settling that follows. |
| `body_retired`, `exec` on `CCleanup` during disposal | `Owner.AddCleanup`, `Owner.RunLate` | On a disposed scope a registered cleanup runs at once, inline, and an exception is recorded. `exec` runs it at once and emits `EvCleanup`, and `EvFail` on failure, with the `Root.Errors` mapping of the `run_cleanups` row. |
| `RRead`, `EvHostRead`, `host_read` | `Signal.Value`, `Memo.TryValue` outside a computation | Answers at its position in the batch over the current signals, and a disposed memo answers from `rs_frozen`. A failed memo gives `EvHostRead n (Fail f)`, as `TryValue` gives `Failed`, and leaves the batch running. A host read wakes nothing and registers no dependency. A read of an effect or unknown node is stuck: an effect has no value. A memo read and then disposed keeps the value the read answered, as in F#, where the read pulls the memo: `host_read_then_dispose_memo`. |
| `apply_dispose` on a memo, `rs_frozen` | `Memo.Dispose`, `Memo.EnsureCurrent` | A disposed memo answers reads with its last value, and a failed one keeps its failure. The last value is the memo's value over the signals current at the disposal's position in the batch, by the owner's ruling. This matches F# for a memo that is clean at its disposal. It differs for a memo whose sources moved with no pull before the disposal: F# keeps the value it last computed, or the type's default if it never ran. That includes a write earlier in the batch to a memo with a live reader, which F# leaves unpulled. See `Awaiting ruling` in `BUGS.md`. Emits `EvDispose`. |
| `apply_dispose` when disposed already | `if not disposed` in `Dispose` | Idempotent: no event. |
| `RDispose` of a signal or unknown node | none | Stuck. `Signal` has no `Dispose` in Core.fs. |
| `run_all_reads` | none | Every read of a run in order, tracked and untracked, cleanups included. `redundant` compares it. The run set uses the tracked `run_reads` only. |
| `computed_from_snapshot` | closures in cleanups | The inputs are one signal snapshot, the disposed memos' values, and the captured environments of the cleanups the run ran. It also covers disposal records. A captured environment comes from the run that registered the cleanup, so a cleanup can log a value from an earlier snapshot, as an F# closure does: `cleanups_first`. Every read of the run answers from the one snapshot. |
| `reference_runs` initial round | `Effect.Start` | The history starts with one round in which every effect runs, in `effect_order`'s order. |
| `run_set`, `settle` | `RunFlush` | A round's run set comes from a snapshot: each effect's last-run tracked reads compared with the graph at the round's start. `CReadUntracked` reads wake nothing. Writes by an effect apply immediately, so a later effect of the round reads them, and effects they wake run in the next round unless their last-run reads are already current. |
| `effect_order`, `rs_round` | the observer positions and queue | A parameter of the tier, indexed by the round's position in the whole history and valid when it permutes each round's effects. The initial round has index 0, and a settling with an empty run set takes no index. For a fixed program and history this expresses any order an engine chooses per flush. Task 12 characterises the engine's order. |
| `observe_full`, `observe_settled` | none | What an engine must preserve. `observe_settled` keeps, per node, the logs and failures since its last `EvRun`, including disposal cleanups' logs, the distinct failures of its history, and whether it is disposed, and for the whole trace every host read in order. Run counts, effect interleaving, and the logs of superseded runs and their cleanups are unobserved. |
| `refines`, `engine_answers` | none | Over any engine, with no import from `Pure/`. `refines` takes one valid order per history, compares every batch prefix, and requires each prefix's engine trace to be a prefix of the whole trace. `engine_answers`, over a fuel-indexed engine, is the converse obligation: some fuel gives a trace whenever the reference settles under every valid order. An engine proof owes both. |
| `fuel` | none | Bounds the rounds of each settling. A flush that keeps waking effects has no reference meaning: `reference_trace` returns `None`, and the spec states flush theorems conditionally on a returned flush. |
| `None` from `exec` | none | A stuck body: an unbound variable, a negative node id, a read of an unknown node or an effect, a write to a non-signal. These have no F# counterpart, since F# bodies hold variables by scope and nodes by reference. A zero divisor is a failure, not a stuck body. |

### The engine program of a reference program

`theories/Pure/Refinement.v` has no Core.fs symbol: it translates a reference program, and F# has no such form.

| Model symbol | Simplification and reason |
|---|---|
| `erase` | Every node is created in one batch, in id order, and each batch of the history follows. The first flush runs each effect in creation order, as `reference_runs`' initial round runs each in the order given. A host building nodes outside a batch runs each effect at its creation: the same runs for a program with no writes. |
| `rename_target` | Reference node `n` is engine node `S n`: `next_id`'s first id is 1 and a reference program can use 0. A computed target shifts in place. Target `-1` reaches node 0, which answers nothing, as the reference's `node_of` does. |
| `rv` | Moves a body's variables off `prev_var`. In F# a variable is a binding, so the collision has no counterpart. |
| `node_cmd` of an id with no node | A memo with no result, so a read has no result, as the reference's unknown node. A disposal or a write of it has no result either. |
| `CMemo` under `erase` | `Pure` and `CmpEq`. A default-policy memo returning a new reference value each run, or `nan`, is `CmpNever` in the model and is not this form. The `cmp_never` rows in this file list which values those are. |
| `input_cmd` of `RRead` | A `CTryRead`, so a failed read's failure is the host read's answer and the program goes on. |
| `project` | Keeps effects' events, disposals and host reads, in the reference's ids. The reference discards a memo's logs (`node_value`), so an engine that runs a memo more or less often is not observed. The harness's trace still holds them. |
| `engine_order` | The order of the live queue at a flush's start. Marks during the flush append to it: `flush_queue` holds those too, and `engine_order_exact_except` relates the runs to both. It is not the order of a flush with a requeue: `engine_order_exact_falsified`. |
| `history_order` | Each round's effects in the order of that round's runs in the engine, from `engine_rounds`. A history-wide order, and an argument the engine's run gives the reference. |
| `dequeued`, `flush_queue` | The entries `RunFlush`'s loop over `_queue` takes, computed by running the model's `drain`. |

### Differential check

`proofs/differential/run.sh` compares `observed` under `current_flags`, extracted by `theories/Extract.v`, with an interpreter of the same programs over the built assembly (`Generate.fsx`, on the harness of `conformance/Harness.fsx`). Agreement is evidence on the programs generated, and proves nothing about other programs. See `README.md` for what it leaves out.

- A body's label is the node whose body it is, and a cleanup's the node of the body that registered it, which `log_label` computes from the state. Host reads are the reads of the program's top level, batches included.
- The scenario `memo_scope_violation` reports the core's `InvalidOperationException` from a pure memo's scope as `-2`, `pure_scope_failure`, as a zero divisor is reported as `-1`. The mapping is local to that scenario, whose harness asserts a second read answers the same exception with no second run. The scenarios `memo_comparer_failure` and `flush_comparer` reach `Memo.CreateWithComparer` by reflection, through `Ctx.MemoThrowingComparer`, copied from `Generate.fsx`.
- A zero divisor raises a new `Boom -1` each time, as `/` raises a new exception, and the trace reports it as `-1`. `Boom f` for any other `f` is one instance, as the `Fail f` row requires. A program raising two zero divisors is excluded, since the model has one failure identity. Such a program with a self-reading memo moves on every F# run and passes the budget, where the model stops.
- Values are `int` under checked arithmetic and `val` is `Z`. An overflow fails the run as a harness failure, and the generator keeps values small.
- `CmpNever` and `CmpThrows` go through the internal `Memo.CreateWithComparer` by reflection, and `CmpEq` through the public constructor.
- An effect's first body can run before its constructor returns, so the interpreter takes the object from `Graph.CurrentComputation` for a `CDispose` of a running effect. F# code holding only the constructor's result has no such reference: `S10` defers the run with a batch.
- The end state, at the program's end and after the closing. Each model field against its F# private field: `n_value` and `value` (a signal through `Peek`), `n_status` and `status`, `n_failure` and the identity of `failure.Error`, `n_freshness` and `freshness`, `n_unannounced` and `unannounced`, `n_runs` and `runs`, `n_disposed` and `disposed`, `n_queued` and `queued`, the length of `source_slots` and `sources.Count`, the length of `observer_items` and `ObserverCount`, the length of `pending` and `queueCount - queueHead`, the root's `o_errors` and `Root.ErrorCount`. A signal shows its value and observers, a memo every field but `queued`, and an effect every field but value, `unannounced` and observers. A rename in `Core.fs` fails the harness, and a change of meaning fails the comparison.
- The closing is a host read of each memo existing when it starts, in id order, then `Graph.Flush`, as `run_flush`. It sits in the trace and is the same command on both sides. The end state before it keeps stale nodes visible, so the closing masks nothing.
- Known limits of the skip rules. Model `None` conflates exhausted fuel and a stuck body, so a model-only stuck goes unseen when the F# is at `budget` or `fatal`. A program that diverges on both sides has no comparison of the trace prefix before the divergence. `excluded` is judged on the F# alone, so what the model does on an excluded program is not compared. The model driver has no watchdog, and the workflow's `timeout-minutes` bounds it.
- `EPrev` reads the previous value from the environment, as `prev_var` does, and the interpreter sets it from the argument `Memo` passes to the body.
- `RANVIER_SKIP_MODE` (`off` by default, `leave-dirty`, `unchecked` or `all`) selects the skip mode of the model side, through `observed_mode`. Mode `off` is `observed` (`observed_mode_off`). The view leaves out the epoch and the stamps.

`Heap/ObserverSet.v` and `Heap/SourceList.v` implement `ObserverSet` and `SourceList` in HeapLang, and `Heap/Ghost.v`
holds the ghost state of the heap graph. The heap tier covers the present engine: `is_graph_at` requires `g_skip`,
`g_epoch` and `g_stamps` at their initial values, and the observer-set code clears no stamp.

| Model symbol | Core.fs symbol | Simplification and reason |
|---|---|---|
| `is_observers`, `item_cells`, `observer_cell`, `blank_cell` | `ObserverSet`: `items`, `count`, `latest` (195-212) | Four fields: the array, `count`, `latest`, and the array's capacity, which HeapLang cannot read from the array. A cell is the .NET pair of observer and slot; Fable's parallel `slots` array is the same pair. Cells past `count` are `(-1, -1)`, the blanking of 330 and 350. In F# a cell `zeroCreate` made and nothing wrote holds 0, and every read is below `count`. An observer is its id. The empty set has capacity 0, as `ObserverSlots.none`. |
| `observers_grow_code` | `grow` (222-235) | The same sizes. The old array is dropped, not freed: HeapLang's logic is affine. |
| `observers_add_code`, `observers_try_add_code`, `observers_scan_code` | `Add` (247-264), `TryAdd` (270-290) | Reference equality is id equality. `tried_val` gives the F# answers: the handle, -1 and -2. |
| `observers_remove_at_code`, `moved_val` | `RemoveAt` (301-357) | A handle holding another observer fails an `assert`, which is stuck: HeapLang has no exceptions. The `MovedIn` call is returned as a notice, as in the pure model, and the source list's trim delivers it. |
| `observers_walk_code`, `observers_walk_loop`, `visitor_spec` | `NotifyDirty`, `NotifyDirtyExcept`, `NotifyCheck` (372-428) | One walk with a visitor closure called on each observer id. The loop's argument is the F# cursor plus one, the pure `walk`'s first argument. `visitor_spec` gives each visit the position and slot of its observer, and lets it mutate the set through `observers_add` and `observers_remove_at`, the mutations of the pure `walk`. |
| `is_source_list`, `source_list_rep`, `src_rep`, `slot_fun`, `slot_val`, `handle_val` | `SourceList`: `first`, `firstHandle`, `rest`, `count`, `cursor`, `held` (540-576) | Six fields. Position 0's source and handle are one field holding a pair, the rest array and its capacity are two more, then `count`, `cursor` and `held`. `None` is -1. Cells past `count` are blank, the blanking of 670-688; as for observers, a never-written F# cell holds 0 and every read is below `count`. `is_source_list` requires the cursor within the slots, which F# keeps and the repeat test at 787 needs. `source_list_rep` is the state inside `Clear`, between its trim and its cursor reset. |
| `held_rep`, `list_val`, `held_build_code`, `held_mem_code`, `sources_holds_code`, `sources_held_before_code` | `held`, `holds`, `heldBefore` (576, 630-653) | The `RefIndex` is a HeapLang list of sources, abstracted to the set of its elements. It exists only for lists longer than `scan_limit`, and then holds every slot's source. Building it is `holds`'s loop, membership a list scan. |
| `resolver`, `is_world`, `obs_part`, `src_part`, `world_in` | object references to `ISource` and `IComputation` | A node is its id, and `res` maps an id to the locations of its observer set and source list. `is_world` holds both structures of every node in the table. |
| `sources_trim_loop`, `sources_trim_from_code` | `trimFrom` (658-694) | Each handle is read when its position is reached, as in F#. The loop bound is `count` read once, as F#'s `for`. `held` is set to `NONE` unconditionally, the same state as the null test. |
| `sources_moved_in_code` | `MovedIn`, `setHandle` (599-607, 715) | Writes the cell without a bounds test, as F#. The world specifications therefore take `edge_match`: `moved_past_list_world` is an incoherent world whose trim the pure model completes by a `MovedIn` past the end, which the heap would write into a blank cell or past the array. |
| `sources_link_code`, `sources_index_add_code`, `sources_append_code`, `sources_add_code` | `Append`, `Add` (729-796) | F#'s order: the new slot is written with -1, the count and cursor set, then `TryAdd`, `holds` and `Add`, then the handle and the index. The add takes the resolver and the computation's id; the source list is resolved from the id. |
| `sources_begin_run_code`, `sources_end_run_code`, `sources_clear_code`, `sources_new_code` | `BeginRun`, `EndRun`, `Clear`, the constructor (722, 803-814) | As F#. |
| `graphG`, `graph_edge`, `graph_edges_auth`, `edge_map` | none | Ghost: an authoritative map from each node to its observer set and source list, with an exclusive fragment per node. |
| `graph_fresh_lb`, `fresh_code`, `fresh_map`, `epoch`, `fell`, `epoch_rule` | `freshness` per node | Ghost: monotone freshness. A node's code is `3 * epoch + rank`. Its ghost epoch advances by one at a fall, a step that lowers the rank, and is unchanged otherwise (`epoch_rule`), so codes only grow (`fresh_code_le`, `fresh_map_grows`). |
| `graph_state`, `graph_state_auth`, `is_graph_at`, `is_graph`, `skip_ok` | none | Ghost agreement between the heap graph and the pure `state`. `is_graph_at` holds the edge world in the heap, requires it coherent (`edge_match`), and requires the table's domain to be the nodes of the state. The node fields and the effect queue are not yet in the heap. |
| `graph_loc`, `graph_locs_auth`, `resolver_extend`, `graph_add_node_code` | object references to new nodes | The graph value is a location holding the resolver. A new node extends the resolver by one closure, which answers the new id and passes the others down the chain. The ghost location map is monotone, so a node's locations agree at every later state. |
