### Probe 1: DOM interfaces and `DispatchProxy`

```fsharp
#r "nuget-cache/fable.core/5.3.0/lib/netstandard2.0/Fable.Core.dll"
#r "nuget-cache/xantham.fable.core/0.2.0/lib/net8.0/Xantham.Fable.Core.dll"
#r "nuget-cache/xantham.fable.core.ts/0.2.1/lib/net8.0/Xantham.Fable.Core.TS.dll"
open System
open System.Reflection
let asm = typeof<Fable.Core.TS.Dom.Node>.Assembly
for n in [ "Node"; "Element"; "HTMLElement"; "HTMLInputElement"; "Event"; "InputEvent"; "EventTarget"; "Document" ] do
    let t = asm.GetTypes () |> Array.find (fun t -> t.FullName = "Fable.Core.TS+Dom+" + n)
    let all = t.GetInterfaces ()
    let methods = (t :: List.ofArray all) |> List.sumBy (fun i -> i.GetMethods().Length)
    printfn "%s interface=%b inherits=%d methods(incl inherited)=%d" n t.IsInterface all.Length methods
type P() =
    inherit DispatchProxy()
    override _.Invoke(m, _) =
        printfn "invoked %s" m.Name
        if m.ReturnType = typeof<Void> then null
        elif m.ReturnType.IsValueType then Activator.CreateInstance m.ReturnType
        else null
let p = DispatchProxy.Create<Fable.Core.TS.Dom.HTMLInputElement, P> ()
p.``checked`` <- true
p.value <- "x"
printfn "%A" ((p :> Fable.Core.TS.Dom.Node) :? Fable.Core.TS.Dom.ARIAMixin)
```

## jsdom loop baseline

`2026-10-21-dom-twin/loop-jsdom.json`, from `benchmarks/frameworks/loop-time.mjs --loop jsdom --runs 10`, behind the bench
lock. Each run appends an exported value to `tests/DelegationChecks.fs`, and the script restores the file afterwards.
Cold is the first sample: the compile with `--noCache`, the first watch edit, the first `node --test`. The compile's
second run rebuilds the cache that `--noCache` skipped, so it is reported as primed and left out of warm. Warm is the
remaining samples, with the lower median. Milliseconds.

| Step | Cold | Primed | Warm median | Warm min | Warm max |
|---|---:|---:|---:|---:|---:|
| `dotnet fable tests/DomTests.fsproj` (one-shot) | 47125 | 47391 | 31164 | 30193 | 34941 |
| `dotnet fable watch`, edit to rewritten `DelegationChecks.js` | 370 | | 364 | 335 | 375 |
| `node --test tests/delegation.test.mjs` | 848 | | 690 | 641 | 910 |

The watch step ends when Fable rewrites the edited module's output; the watcher is ready at the `Watching` line Fable
prints after its first compile. A jsdom edit-to-result loop takes about 1.1 s with a warm watch, and about 32 s through
a one-shot compile.

The baseline above was measured with Fable 5.18.0, before #152 replaced Fable with Fickl 0.3.0; `loop-time.mjs` now runs
`dotnet fickl`, and phase 6 re-measures the jsdom loop with Fickl before comparing it with the twin.

Machine: 24 logical processors, Windows 11 (10.0.26200), .NET SDK 10.0.402, Node.js 26.7.0.

## Native form

Task 3 moved Hydration's seven host primitives (`firstChildOf`, `following`, `absent`, `removeNode`, `elementById`,
`textOf`, and `isRootMarker`, which kept a local `#if` pair) into `experiments/Ranvier.View.Portable/Native.fs`. Each
primitive is a `#if FABLE_COMPILER` Emit declaration followed by its `#else` .NET body.

- Gate 3 is the evidence for this task: `generated-diff.mjs generated-tests-base generated-tests` lists no file, Fable
  inlines every Emit primitive at its call sites, and no `Native.js` is emitted.
- Gate 1 holds, but proves nothing about Hydration: none of the six sugar-size bundles holds hydration code. Gate 1
  first covers moved code in phase 1, where Mounting and TemplateDom change.
- A file-local inline alias (`let inline private following node = Native.nextOrNull node`) changes the output: Fable
  binds each argument of an inlined F# function to a temporary, and `Hydration.js` gained `node_2 = node_1` lines.
  Call sites call `Native.<name>` directly.
- `PackagingChecks` forbids Emits touching `document` in Portable files other than `Native.fs`. For `Native.fs` it
  requires every Emit to sit inside a `#if FABLE_COMPILER` block whose `#else` defines the same top-level names, and it
  checks itself against an unguarded Emit, a missing .NET body and a block without `#else`.

## The departures seam on .NET

`Departures.seam` is one object for the process on .NET, as the JavaScript module's object is for a page. A
registration on any thread turns `Enabled` or `ReflowEnabled` on for every later mount on every thread, and nothing
turns them off. Twin tests that need a clean seam use `Departures.createSeam ()`.

## Platform-specific cases

The twin runs every shared range, template, delegation, testing-API, boundary and placement case except the two below,
which run under jsdom only. The cases that count or fail DOM calls do so through `Harness.Intercept` on both hosts. The
conformance cases use 54 DOM members on the twin (`experiments/Ranvier.View.Twin/members.txt`).

| Module | Case | Reason |
| --- | --- | --- |
| TemplateChecks | an each end swap stops placing rows once the mount is disposed | defines a custom element |
| TemplateChecks | markup restructured by the HTML parser fails compilation | the twin parser rejects a table without tbody, before template compilation |

## The two harnesses

Both harnesses give a case the same environment:

- **The document.** The twin gives each case a fresh document. The jsdom runner keeps one jsdom for the run and empties
  its head and body, clears their attributes and blurs the active element before each case. One document serves the
  run, as one serves a page: Foundation keeps a definition's compiled template on the definition, so a template
  compiled in a closed window's document would reach later cases with that window's prototypes. Listeners a case adds
  to `document` or `window` stay for later jsdom cases.
- **The clock.** `conformance-host.mjs` replaces jsdom's `queueMicrotask`, `setTimeout`, `clearTimeout`,
  `requestAnimationFrame` and `cancelAnimationFrame` with the twin clock's semantics: the view's queued microtasks and
  `Post` share one queue that only `RunMicrotasks` drains, and `AdvanceBy` runs due timers and 16 ms animation frames in
  due order, draining the queue after each callback. `Date` follows the clock. Promise reactions still run natively
  under jsdom.
- **Listener failures.** jsdom's "Not implemented" notices (form submission, navigation) are left out of
  `ListenerErrors`; the twin has no counterpart.
- **Interception.** `Intercept` wraps a DOM method of one node, or of every node when the target is null: jsdom
  patches the instance or the node prototypes, and the twin's bridge consults a per-document table before its member
  table. The twin's host adds and removes the view's listeners through `addEventListener` and `removeEventListener`,
  as the JavaScript does, so an interception sees them.

The delegation cases run the .NET port of the delegated walk on the twin: nested keyed mounts, `stopPropagation`,
inner and outer hosts, a native stop between target and host, a detached host, non-bubbling direct listeners, and,
through interception, shared, moved and self-disposing hosts. The range, template and delegation cases include no
head entries and no hydration, so the `keepHead` copy path and the hydration rollback snapshots run first with the
document and hydration cases.
