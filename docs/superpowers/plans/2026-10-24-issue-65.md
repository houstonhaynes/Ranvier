**Goal:** A traced graph streams its trace log to a sink while it runs. After each flush, on the graph thread, an exporter reads the log from its cursor, encodes the events as schema 3 dump lines (the #166 envelope), and queues them in a bounded queue that the sink drains asynchronously. A full queue either waits (no loss) or drops and records a gap. The exporter can checkpoint the exported prefix so the log stays bounded. The untraced build is unchanged.

## Core and view state

This is core trace work in `src/Ranvier`, compiled only with `RanvierTrace=true`. It touches no view code.

**Core primitives used:**

- `Trace.eventsSince` / `Trace.checkpointOf` (#165): the exporter's cursor read and its resync point.
- `Trace.checkpoint` (#165): truncates the exported prefix; its `gate` (graph thread, between flushes) sets where the exporter may call it.
- `TraceModel.dumpTextEncoded` and `TraceCodecs` (#166): the schema 3 header, snapshot and event lines, with payloads encoded by the user's codecs.
- `Graph.RunFlush` (`src/Ranvier/Core.fs`): the end of each flush is the drain point. A flush never nests (`flushing` absorbs re-entry), so every completed `RunFlush` is an outermost flush.
- `Graph.Dispatch` (#167): resumes a waiting exporter and runs an acknowledged checkpoint on the graph thread.
- `Platform.whenDone`: settles a sink's `Task` on .NET and Fable alike.

**View-owned state:** none.

**Exporter-owned state:** the cursor (the last seq read), the bounded queue of encoded records, the pending gap range and the fault. Each is consumer state over the core's log, not a duplicate of a core primitive.

## Design

### API

In a new file `src/Ranvier/TraceExport.fs` (traced only, after `TraceContract.fs`, before `TraceApi.fs`), plus `Trace.export` in `TraceApi.fs`:

```fsharp
/// One unit of the exported stream.
[<RequireQualifiedAccess>]
type TraceExportRecord =
    /// The dump header line and snapshot line the stream starts from.
    | Header of text: string
    /// Schema 3 event lines for seqs From..To, each ending in \n.
    | Events of from: int * ``to``: int * text: string
    /// Seqs From..To were dropped or folded before export.
    | Gap of from: int * ``to``: int

type ITraceSink =
    /// Names the sink; a checkpoint the exporter takes is named after it.
    abstract Name: string
    /// Completes when the sink holds the record.
    abstract Write: TraceExportRecord -> Task

[<RequireQualifiedAccess>]
type TraceExportFull =
    /// Keeps the events in the log and resumes when the queue has room. Loses no event.
    | Wait
    /// Drops the incoming batch and records its seqs in a gap.
    | Drop

[<RequireQualifiedAccess>]
type TraceExportCheckpoint =
    | Never
    /// Checkpoints once a batch is queued or dropped: the log stays bounded under a stalled sink.
    | Enqueued
    /// Checkpoints once the sink completes a batch's Write.
    | Acknowledged

type SinkPolicy = { Capacity: int; Full: TraceExportFull; Checkpoint: TraceExportCheckpoint; Codecs: TraceCodecs }

type TraceExport =   // IDisposable
    member Drain: unit -> unit          // graph thread: reads and queues now, outside a flush
    member Completion: Task             // completes after Dispose once the sink holds every queued record; faults with the sink's error
    member Dropped: int                 // events dropped so far

module Trace =
    val export: graph: Graph -> sink: ITraceSink -> policy: SinkPolicy -> TraceExport
```

Shape choices and why:

- **`Trace.export graph sink policy`** is the issue's shape. It returns `TraceExport`, which implements `IDisposable` as the issue asks, and adds `Drain` and `Completion`: a write with no queued effect runs no flush, and a test or a shutdown needs to know when the sink holds everything. A class handle with members matches `Graph` and `Owner`.
- **A Ranvier-owned bounded queue, not `System.Threading.Channels`.** `src/Ranvier` targets `netstandard2.1`, where Channels is a separate package, and Fable has no Channels. One queue serves both platforms. Its surface mirrors `ChannelWriter`: `TryWrite` returns `false` on a full queue, and the `Wait` path is an asynchronous write that resumes through `Graph.Dispatch` when the sink frees a slot. Under `Wait` the events stay in the trace log, so the log is the overflow buffer and nothing is lost (criterion 2). Under `Drop` a `false` from `TryWrite` records the batch's seqs in the pending gap, never a silent loss.
- **Capacity counts events**, so memory is bounded by event volume, not by batch count.
- **`Drop` drops the incoming batch only.** The gap then always sits at the tail of the queue and merges with the next drop, so one `Gap` record names one contiguous range. `DropOldest` would split the stream around queued batches and adds nothing a diagnostic stream needs.
- **Three checkpoint modes, against the issue's single `CheckpointAfterDrain`.** The issue's shape checkpoints once the sink acknowledges. Under a stalled sink no batch is ever acknowledged, so the log would grow without bound and criterion 1 could not hold. `Enqueued` checkpoints once the encoded copy is queued or dropped: the queue holds the text, and the log releases the payloads. `Acknowledged` is the issue's semantics, for sinks whose loss on a crash matters. The checkpoint is named after `ITraceSink.Name`, the place the earlier events live, which matches the dump header's `checkpoint` field.
- **Records carry encoded text.** Encoding runs on the graph thread, after the flush (below), so codecs read payloads where they were written. The sink receives final lines and needs no Ranvier types beyond the record.
- **`Gap` is a record kind, and in JSONL a line `{"gap":{"from":F,"to":T}}`.** `TraceModel.parseDump` and `TraceContract.parseDumpWith` read gap lines into a new `TraceDump.Gaps: (int * int) list` (empty for every existing dump), so a file with gaps parses instead of failing. An event after a gap resolves a cause inside the gap as `BeforeCheckpoint`.

### Drain point

`RunFlush` gains, between `Tracer.FlushEnd this` and `this.LeaveAmbient previousAmbient` in its `finally`, a call `Tracer.Flushed this`. (A call after `LeaveAmbient` ends the `finally` on a statement other than the inlined `match`, and the untraced `RunFlush` grows by 8 IL bytes although the call itself is removed; measured on 2026-10-25.) `Tracer.Flushed` is `[<Conditional("RANVIER_TRACE")>]` like every hook, so the untraced IL is unchanged (criterion 4, checked by `tools/verify-trace.fsx`). It runs each exporter registered on the graph's `TraceLog`, outside the flush and with the ambient graph restored. The exporter catches its own exceptions (a strict codec's `TraceCodecException`, a sink that throws synchronously) into its fault, which `Completion` reports; the graph never sees them.

A drain:

1. If the cursor is behind `checkpointOf graph` (another caller checkpointed past it), records `Gap (cursor + 1, checkpoint seq)` and moves the cursor.
2. Reads `eventsSince graph cursor`; returns on an empty read.
3. Encodes the batch to schema 3 lines.
4. `TryWrite` to the queue. On `false`: `Wait` leaves the cursor and arms a resume; `Drop` extends the pending gap. On `true`, a pending gap is queued first.
5. Under `Enqueued`, checkpoints at the batch's last seq when the gate allows it, and at the previous seq when `LabelFollows` refuses that one. A checkpoint runs once `Capacity` exported events lie past the previous one, and at the stream's end: its cost grows with the graph (collectable nodes, the snapshot, the pending marks), so a checkpoint per flush would cost O(live nodes) on every flush. The log keeps fewer than `Capacity` exported events.

The first record is always `Header`: the dump header and snapshot of `checkpointOf graph` at `export` time, schema 3, with `seqFrom` the cursor plus one. `TraceModel` gains `dumpHeader` and `eventLines`, factored out of `dumpTextEncoded`, so `Header` text plus the concatenated `Events` text equals `Trace.dumpTextWith graph codecs` for the same run (criterion 3). `Trace.dumpText` writes schema 1 or 2; the comparison is against `dumpTextWith`, the schema 3 form of the same dump.

### Reference sinks

`TraceSinks.memory () : MemoryTraceSink` (both platforms): holds the records in order; `Text` concatenates `Header`, `Events` and gap lines. A `stall` / `release` pair makes its `Write` tasks wait, for the stress tests. `TraceSinks.jsonl (path: string)` (.NET only, `#if !FABLE_COMPILER`): appends each record's text to the file and completes when the write is flushed. No store client enters `src/Ranvier` (criterion 5).

### C# surface

`Ranvier.CSharp` `Tracing` gains `Export(graph, sink, capacity, full, checkpoint, codecs)` returning `TraceExport`, in the shape of `EventsSince` and `Checkpoint`, with the policy's fields as parameters, and `MemorySink()` and `JsonlSink(path)`.
