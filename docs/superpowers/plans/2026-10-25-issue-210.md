# Issue #210: keyed persisted inputs over an IStateStore (Ranvier.Persistence)

Branch `issue/210`, cut from `origin/integration/issues`; the PR base is `integration/issues`. The branch is never
rebased or force-pushed: when `origin/integration/issues` moves, merge it into `issue/210` and push normally.

## Goal

A new package `src/Ranvier.Persistence` (`net10.0;netstandard2.1`, `RanvierAotClean`, Fable-compatible, references
`Ranvier` and `Ranvier.Wire` only) keeps a graph's inputs (signals, keyed collections, an `Mvu` model) across a
process restart or page reload, under keys the application chooses. Derived nodes recompute from the restored inputs.
Milestone 1.0.0-rc. Stores: in-memory, file (.NET, write-temporary-then-rename) and `localStorage` (Fable).

## Acceptance criteria (copied from the issue)

1. **Zero cost when unused.** The counter bench shows no instruction or allocation change for graphs with no persisted
   nodes, and reports the per-write cost of a persisted signal. The untraced IL of `src/Ranvier` is unchanged, unless
   decision 4 adds a hook.
2. **Coalescing.** A batch writing N persisted signals produces exactly one `SaveMany` with N records. Writing the same
   key twice in one batch saves it once. Both hold on the default dispatcher and on a
   `SynchronizationContextDispatcher`, built on existing primitives first (decision 4 covers the fallback).
3. **Round trip.** A test writes persisted inputs, calls `FlushAsync`, builds a fresh graph from a new `loadAsync` over
   the same file store, and reads equal input values. Derived memos equal those of an uninterrupted run. The first read
   of a persisted signal returns the stored value, and no effect observes a fallback-then-stored transition.
4. **Versioning.** An older stored version runs its migrations in order. A newer one fails `loadAsync` with a typed
   error naming the key. A decode failure fails `loadAsync` with a typed error naming the key, and with the discard
   option it uses the fallback instead (decision 3). A store-wide buster mismatch discards every record.
5. **Collections.** Editing one row of a persisted keyed collection saves that row only (row store) or one document
   (document store). A restored collection keeps insertion order.
6. **Durability point.** `FlushAsync` completes only after the store's `SaveMany` task for every earlier write has
   completed, and faults with that task's exception.
7. **Journal position.** A session saved alongside an attached journal records the position of the last journal entry
   that the saved records include, and `loadAsync` exposes it. #197 consumes it; this issue does not implement the
   tail replay.
8. **Stores.** The in-memory store, a file store (.NET, write-temporary-then-rename) and a `localStorage` store (Fable)
   each pass one shared conformance suite (load, save, delete, version mismatch, buster). #185's adapters reuse the
   suite.
9. **Platforms.** The NativeAOT smoke app publishes with a persisted signal and no trim or AOT warnings. A Fable test
   round-trips a record and a union through the `localStorage` store with Wire codecs.
10. **Docs.** A guide page states that persisted inputs belong at the root or in a keyed factory, that derived nodes
    recompute, and that the trace dump is not a persistence format. The journal guide's restore section links to it.

## Binding decisions (user, 2026-10-25)

1. 1.0.0-rc; stores limited to in-memory, file and `localStorage`.
2. Codec: the journal's `JournalCodec<'T>` plus ordered migrations (`PersistCodec<'T>`). A journaled, persisted signal
   uses one codec value.
3. Decode failure fails `loadAsync` with a typed error naming the key; a session option opts into discarding the record
   and using the fallback.
4. `src/Ranvier` changes only if criterion 2 cannot be met with existing primitives. Then, and only then: a public
   untraced `Graph.AfterFlush` hook with one guarded check per flush, measured on the counter bench (`gate-lock bench`)
   and listed with its IL change in the PR body.
5. One package holding the three stores. Database adapters stay in #185.
6. Last writer wins. `StoredRecord` carries `ETag: string option`, ignored by the v1 stores.

## Core and view state

No view code is involved; the section records the core/package split that view-uses-core.md asks for.

- **Core primitives used:**
  - `Signal<'T>`: the persisted value, constructed with the decoded stored value as `initial`, so the first read
    returns it and no effect sees a fallback-then-stored transition.
  - `createEffectOn`: change detection per persisted input. Its `act` encodes the value on the graph thread and puts
    the record in the dirty map.
  - A package-private drain `Signal<int>` and one drain effect per session: the first dirty mark of a flush writes the
    drain signal, which queues the drain effect behind every persisted effect already queued in that flush. The drain
    effect hands the dirty map to the save queue. This is the "existing primitives first" route of criterion 2.
  - `KeyedCollection` with `Rows.NewValueReader` and `KeyChange`: row-level changes for the row layout.
  - `onCleanup` / `Owner`: detaching a persisted input when its owner is disposed.
  - `Graph.Current`: the graph a persisted input is created in (the same convention as `createSignal`).
- **Package-owned state:** the decoded preloaded values, the dirty-record map, the outbound save chain and the pending
  save tasks for `FlushAsync`, and the last journal `Seq` seen by the position-tracking journal wrapper. The core holds
  no IO state.

## Design

### Public API (chosen shapes, and why they differ from the issue's sketch)

The sketch passes `keys: string list` to `loadAsync` and the codec to `Persist.signal`. Criterion 4 requires
`loadAsync` itself to fail on a newer version or a decode failure, so `loadAsync` must know each key's codec. Keys are
therefore declared values carrying their codec, the way `Journal.key` pairs a key with a `JournalCodec`:

```fsharp
type StoredRecord = { Key: string; Version: int; Payload: string; ETag: string option }

type IStateStore =
    abstract LoadMany: keys: string list -> Task<StoredRecord list>
    abstract SaveMany: records: StoredRecord list -> Task
    abstract DeleteMany: keys: string list -> Task

type PersistMigration = { From: int; Migrate: string -> Result<string, string> }   // From -> From + 1
type PersistCodec<'T> = { Codec: JournalCodec<'T>; Migrations: PersistMigration list }

type PersistFailure =
    | NewerVersion of stored: int * supported: int
    | MissingMigration of from: int
    | MigrationFailed of from: int * message: string
    | DecodeFailed of message: string
exception PersistLoadException of key: string * failure: PersistFailure   // Message names the key

type PersistOptions = { Buster: string option; DiscardUndecodable: bool }

type IPersistKey = abstract Key: string           // implemented by the declarations below
type PersistKey<'T>                                // a value key
type PersistRows<'K, 'V>                           // a collection key, row or document layout

module PersistCodec =
    val ofJournal: JournalCodec<'T> -> PersistCodec<'T>
    val withMigration: from: int -> migrate: (string -> Result<string, string>) -> PersistCodec<'T> -> PersistCodec<'T>

module Persist =
    val key: key: string -> codec: PersistCodec<'T> -> PersistKey<'T>
    val rows: key: string -> codec: PersistCodec<'V> -> keyOf: ('V -> 'K) -> keyText: ('K -> string) -> PersistRows<'K, 'V>
    val document: key: string -> codec: PersistCodec<'V> -> keyOf: ('V -> 'K) -> PersistRows<'K, 'V>
    val loadAsync: store: IStateStore -> keys: IPersistKey list -> Task<PersistSession>
    val loadWith: options: PersistOptions -> store: IStateStore -> keys: IPersistKey list -> Task<PersistSession>
    val signal: session: PersistSession -> key: PersistKey<'T> -> fallback: 'T -> Signal<'T>
    val collection: session: PersistSession -> key: PersistRows<'K, 'V> -> KeyedCollection<'K, 'V>
    val restore: session: PersistSession -> key: PersistKey<'T> -> fallback: 'T -> 'T
    val track: session: PersistSession -> key: PersistKey<'T> -> read: (unit -> 'T) -> unit

type PersistSession =
    member FlushAsync: unit -> Task
    member Position: int option
    member Journal: inner: IInputJournal -> IInputJournal
```

- `Persist.mvu` is not offered: `Mvu` lives in `Ranvier.Elmish`, and the package references `Ranvier` and
  `Ranvier.Wire` only (decision 5 and the user ruling). An `Mvu` model persists with
  `Mvu.create (Persist.restore session modelKey initModel) update`, then `Persist.track session modelKey (fun () -> mvu.Model)`.
  The guide shows it, and a test in the .NET test project (which references `Ranvier.Elmish`) proves it.
- `PersistSession` creates nodes in `Graph.Current`, like `createSignal`. One session serves one graph; a second graph
  raises `InvalidOperationException` naming both.
- A Wire codec adapts to `JournalCodec` as the journal guide shows; `PersistCodec.ofJournal` lifts it.

### Reserved records

Keys beginning `$ranvier/` are reserved; `Persist.key` and `Persist.rows` reject them.

- `$ranvier/buster`: the session's `Buster`. On load, a stored buster unequal to `options.Buster` discards every record
  of the load (they read as absent and use fallbacks) and the next save rewrites the buster.
- `$ranvier/position`: the journal `Seq` captured with the last saved batch (criterion 7). Loaded with every session.

### Collections (criterion 5)

- Row layout (`Persist.rows`): one record per row under `key + "/" + keyText rowKey`, and an index record under `key`
  listing the row keys in insertion order. Editing one row's value saves that row record only; adding or removing a
  row also saves the index; removing deletes the row record (`DeleteMany`). `loadAsync` reads the index, then loads its
  rows in a second `LoadMany`.
- Document layout (`Persist.document`): one record under `key` holding every row, length-prefixed, in insertion order.
  Any edit saves that one record.
- Restoring adds the rows in stored order, so `Rows` keeps insertion order.

### Coalescing and durability (criteria 2 and 6)

- Every persisted input's `createEffectOn` act encodes on the graph thread and sets `dirty[key] <- record` (same key
  twice in one batch: last value, one record). The first mark in a flush increments the drain signal.
- The drain effect swaps out the dirty map and appends `store.SaveMany records` to the save chain: each save starts
  after the previous one completes, so last writer wins in write order. Deletions go through the same chain.
- `FlushAsync` returns a task over every save started before the call; it faults with the first faulted save's
  exception. A faulted save does not stop later saves.
- Step 5 proves one `SaveMany` per batch on `ManualDispatcher`/`ImmediateDispatcher` (the default resolutions) and on
  `SynchronizationContextDispatcher`. If the drain effect cannot be ordered after every persisted effect of the flush
  on one of them, step 5b adds the `Graph.AfterFlush` hook (decision 4) and the drain moves onto it.

### Stores (criterion 8)

- `MemoryStateStore`: a dictionary; completed tasks.
- `FileStateStore(directory)` (.NET only): one file per key (key escaped to a file name), written to `name.tmp` then
  `File.Move(tmp, name, overwrite = true)`; `LoadMany` skips absent files.
- `LocalStorageStateStore(prefix, ?storage)` (Fable only): `storage` defaults to `window.localStorage`; the Node.js
  Fable tests pass an in-memory `Storage` shim, since Node exposes no `localStorage` without a flag.
- The conformance suite (`tests/Ranvier.Persistence.Tests/StoreConformance.fs`, Expecto, compiled into the .NET test
  project and into `fable/Ranvier.Tests.Fable`) takes a store factory and covers load, save, delete, version mismatch
  and buster. #185's adapters reuse it by referencing the file.

### Journal position (criterion 7)

`session.Journal inner` returns an `IInputJournal` that forwards to `inner` and remembers the last non-`Flush` entry's
`Seq`. The drain captures that `Seq` on the graph thread with the dirty records and saves `$ranvier/position` in the
same `SaveMany`. `PersistSession.Position` exposes the loaded value. The application builds the graph with
`GraphOptions` whose journal is `session.Journal inner`, after `loadAsync`.
