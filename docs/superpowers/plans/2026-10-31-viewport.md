# G02/G12 viewport service (DOM alpha.28)

## Core and view state

- **Core primitives used:** none inside `Ranvier.Dom`. A view that subscribes calls `ViewportService.Subscribe` under
  an `Owner` and registers the handle's `Dispose` with `onCleanup`; values derived from changes are written to
  signals inside `batch`.
- **View-owned state:** none. The service keeps its subscriber list, its window listeners and the media query list
  armed for the current device pixel ratio: registrations on engine event targets.

## Contract

`src/Ranvier.Dom/Viewport.fs`: `ViewportMetrics` (inner/outer CSS size, `DevicePixelRatio`), `ViewportChange`
(`Resized | Scrolled | ScrollEnded | VisibilityChanged | Activation | ScaleChanged`), `ViewportMediaQuery`,
`ViewportProvider` (window, document, metrics, `matchMedia`) and `ViewportService` (`Current`, `Hidden`,
`Subscribe`, `Dispose`). `Viewport.create` listens on the window for `resize` and window `focus`/`blur`, and for
`scroll`, `scrollend` and `visibilitychange` targeted at the document; it re-arms
`matchMedia("(resolution: <ratio>dppx)")` after each `change`. Disposal removes every listener and releases the
armed list.

Providers: `BrowserViewport.forDocument` (Fable, the document's Window); the native provider in
`Ranvier.View.WebCore/Viewport.fs` (Views 0.1.18) over `rv_host_window_event_target`, `rv_host_window_metrics` and
`rv_host_match_media` (Native27/ABI35).

## Proof

The shared conformance fixture `Viewport.fs` in Views runs on native JIT, NativeAOT and Chromium: metrics against
paint size per scale, change order for resize, scroll, scale and activation, native-only visibility order
(`visibilitychange` at the document with `document.hidden` matching), and teardown (subscription dispose, service
dispose, dispose after host destroy). Native engine evidence: Ranvier.WebCore `docs/VIEWPORT-PLAN.md`.
