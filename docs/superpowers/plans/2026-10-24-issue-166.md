## Current state (2026-10-24, `issue/165` tip `b033aa4d`)

- Structured results already exist as immutable F# records and unions: `TraceSnapshot` (nodes, owners, sources, observers), `Why` / `WhyStep` / `WhyRoot`, `WhyNotReason`, `TraceWaiting` / `TraceFlight`, `TraceHistory` / `TraceRun`, `TraceOrigin`, `TraceDump`, `TraceCheckpoint`. Their `ToString` is F# record syntax, not a contract.
- Live object references leak through two fields: `TraceEvent.Payload: obj` and `TraceRun.Value: obj option`; `TraceOrigin.Site: obj`. These are application objects that can mutate after recording.
- `TraceModel.dumpText` writes JSONL schema 1, or 2 when timed nodes exist; `parseDump` (.NET only) reads 1 and 2 and rejects others with `FormatException`. Payloads are written as `payloadText`: exact for `int`, `string`, `bool`, `float`, null, and `valueText` (diagnostic text) for everything else, with no marker telling the two apart.
- Node ids are graph-local counters. Identity paths are built from labels (`Trace.named`, `Trace.label`) or else creation sites (`file:line`), with `#n` sibling and `@k` incarnation suffixes. Nothing documents which of these survive a rerun or a code edit.
- There are no committed dump fixtures; dump tests regenerate and compare in-process.

## Design

All new public code goes in one new traced-only file, `src/Ranvier/TraceContract.fs`, compiled after `TraceModel.fs` and before `TraceApi.fs`, plus graph-taking entry points in `TraceApi.fs` (`Trace.*`). The writer side is Fable-compatible (hand-written JSON, as `TraceModel.dumpText` does); readers are .NET only, as `parseDump` is. The existing records and `TraceModel` queries stay unchanged, so `Trace.render`, `ToString` and the existing tests keep working.

### Node identity scopes

Documented in the tracing guide and expressed by `TraceNodeRef`:

| Scope | Value | Stability |
|---|---|---|
| Runtime | `Node: int` | One graph instance. Never stable across runs. The ref carries no graph discriminator: every graph's root owner id is 1, and a process-unique id would make recorded traces and fixtures depend on run order. A caller holding refs from several graphs keeps each with its graph. |
| Located path | an identity path holding at least one site segment | Stable across reruns of the same build with the same creation order; changes when an edit moves a creation site. |
| Named path | an identity path whose every segment is a label | Stable across reruns and code edits that keep the labelled tree and its creation order. The persisted-reference identity. |

`TraceNodeRef = { Node: int; Path: string; Stability: TracePathStability; Label: string option }`, with `TracePathStability = Named | Located`. Application-defined stable identity is the named path: labels are already Ranvier's naming convention (`Trace.named`, `Trace.label`), so no new keying API is added. A path with an `@k` incarnation suffix stays `Named` (the incarnation counts creations, which the same program repeats). `#n` sibling suffixes are deterministic for the same creation order and stay as they are.

### Lookups

`TraceAddress = ById of int | ByPath of string` and `TraceLookup`:

- `Live of TraceNodeRef` — present and not disposed.
- `Disposed of TraceNodeRef * seq: int` — disposed in retained history or the checkpoint.
- `Checkpointed of TraceNodeRef` — present only in the checkpoint snapshot (its creation is outside retained history).
- `Missing` — the log has no node with the address.
- `Foreign` — an `INode` from another graph or an untraced node (`Trace.lookupNode graph node`).

### Payloads and codecs

`TracePayload`:

- `Null`
- `Exact of TraceScalar` (`Int`, `String`, `Bool`, `Float`) — lossless, for the four types `payloadText` already writes exactly.
- `Encoded of codec: string * version: int * data: string` — lossless through an application codec.
- `Lossy of text: string` — diagnostic text only (`valueText`), never decodable. Explicit marker.

`TraceCodec = { Name: string; Version: int; Encode: obj -> string option; Decode: string -> obj }` (a record of functions, matching `TraceModel`'s function-valued options; Fable erases runtime types, so a codec claims a value by returning `Some`). `TraceCodecs` is an ordered list: the first codec whose `Encode` returns `Some` wins; no match gives `Lossy`, or raises `TraceCodecException` naming the value's type under `TraceCodecs.strict`. Decoding an `Encoded` payload whose codec or version is not registered raises, never falls back to text.

### Structured documents

Contract values hold only ints, strings, bools, floats, options, lists, maps, sets and contract types — no `obj`, no live references, no `INode`:

- `TraceGraphState`: `Schema`, `Seq`, `Root`, `Checkpoint: string option`, `SeqFrom`, nodes (`TraceNodeRef` + kind, owner, status, runs, last run, value as `TracePayload`), owners, and dependency edges (`Sources`, `Observers`). A value recorded in retained events is encoded through the codecs; a value only in the checkpoint snapshot is `Lossy` of its folded text.
- Provenance: `Why`, `WhyNotReason`, `TraceWaiting` already hold only ints, strings and unions, and are reused as they are. `TraceHistory` is projected to `TraceRunState` (`TraceRun` with `Value: TracePayload option`). Causes outside retained history keep `WhyRoot.BeforeCheckpoint`.
- Each query result is wrapped as `TraceDocument = { Schema: int; Kind: string; Seq: int; Body: ... }` in the JSON projection, so a document read alone carries its version and its read point.

`TraceJson` (Fable-compatible writer, .NET reader) projects each to JSON. Union cases are `{"case":"Name", ...fields}`; ids are numbers; options are `null`; lists are arrays; maps are arrays of `[key, value]` pairs in key order (as the schema 1 snapshot already writes), so the text is deterministic.

### Versioning and compatibility policy

- One schema integer covers dumps and documents. Schema 3 is this issue's: dumps with structured payloads, and the `TraceJson` documents.
- Writers emit the lowest schema that represents the content: `Trace.dumpText` keeps writing schema 1 or 2 byte for byte; `Trace.dumpTextWith codecs` and every `TraceJson` document write schema 3.
- A reader accepts every schema from 1 to its current one, and raises `FormatException` naming the schema for any other. A schema 1 or 2 payload reads as `Exact` for the four scalar types' text and `Lossy` otherwise, because those schemas carry no marker.
- A change that removes or renames a field, changes a field's meaning, or adds a field a reader must understand bumps the schema. Committed fixtures pin each supported schema.
- The guide's "may change before the first release" note stays; this policy governs changes from schema 3 on.

## Decisions

- **No new identity API.** The issue leaves the shape of application-defined identity open. Labels are the existing convention, so a fully labelled path is the persisted identity; adding a key API would duplicate `Trace.named`.
- **Reuse provenance records.** `Why`, `WhyNotReason` and `TraceWaiting` already hold only immutable data, so the contract reuses them rather than defining parallel types; only records holding `obj` get contract projections.
- **Lossy by default, strict on request.** Tracing is a development tool and most payloads have no codec; failing every dump would make dumps unusable. `TraceCodecs.strict` gives the explicit failure for replay consumers.
- **Schema 1 and 2 untouched.** Existing dumps and their consumers keep their exact text; structured payloads are opt-in through `dumpTextWith`.
