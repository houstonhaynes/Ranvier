# #185: persistent store adapters

Initial investigation at `4154db85`, 2026-10-26. Issue: [#185](https://github.com/shayanhabibi/Ranvier/issues/185).

## Agreed order

Start with Marten, then KurrentDB. Follow with an Equinox/FsCodec integration sample and a Kafka journal sink.
The user accepted this order after asking about supporting all four. The issue's candidates are a useful shortlist;
they are not an established popularity ranking.

## Existing contracts

- `src/Ranvier.Persistence/Types.fs`: `IStateStore` has `LoadMany`, `SaveMany`, `DeleteMany` and `Clear`.
  `SaveMany` returns `Task`, without updated records or ETags. The existing stores use last-writer-wins.
- `StoredRecord.ETag` is an optional string reserved for optimistic stores.
- `tests/Ranvier.Persistence.Tests/StoreConformance.fs` exposes `suite name create`. Each `create ()` must
  return an empty store. Its ten cases cover storage, deletion, clearing, unusual keys, migrations, newer versions
  and busters. It compares key/version/payload, allowing an adapter to return generated ETags.
- `src/Ranvier/Types.fs`: `IInputJournal.Record : JournalEntry -> unit` runs synchronously on the graph thread.
  A remote journal needs a separately specified durability boundary, queue limit and failure policy.

Both the core and persistence projects passed fresh `fslangmcp check` during this investigation.

## ETags need an explicit contract

`PersistCodec.encode` makes records with `ETag = None`. `PersistSession` queues those records without carrying
the loaded ETag forward; it also writes reserved metadata records with `None`.

A SageFs probe loaded `count=2` with `ETag=Some "loaded-v1"`, created a persisted signal, changed it to 3
and waited for `FlushAsync`. A forwarding store captured the outgoing ETags:

```text
restored value = 2
saved ETags = [None]
```

Therefore an adapter accepting explicit ETags does not automatically make ordinary `Persist.signal` writes
optimistic. Keep #210's current last-writer-wins semantics and document this distinction.

Proposed first adapter contract:

- A load returns the backend's current version as an opaque ETag.
- `SaveMany` with `None` is an unconditional upsert.
- `SaveMany` with `Some tag` succeeds only if that record still exists at that version; a stale or deleted
  record faults the save. The whole batch rolls back on a conflict.
- Successful saves assign a new ETag; callers reload to get it before their next conditional save.
- Deletes and clear remain unconditional, matching the existing interface.

Automatic optimistic writes through `PersistSession` would need a separate design for carrying versions through
load, queued saves, successful acknowledgements and retries. Avoid hiding a mutable version cache in a shared
adapter instance: that could let two graph sessions overwrite each other.

## First implementation slice: Marten state store

Use a separate .NET adapter package outside `src/Ranvier` and `src/Ranvier.Persistence`. The dependency direction
is adapter -> Marten + Ranvier.Persistence; the core packages acquire no store client dependency.
Marten 9.54.1 was the latest stable package checked on 2026-10-26.

Use a caller-owned `IDocumentStore`; each operation opens and disposes its own session. Partition records by an
explicit application scope. `Clear` removes records only in that scope, including reserved persistence metadata.
Document identity must preserve ordinal, case-sensitive application keys and avoid collisions between scopes.
Store the codec version separately from the database concurrency version.

Implementation checks, in order:

1. Run the existing ten-case conformance suite against isolated PostgreSQL scopes.
2. Add a shared optimistic-store suite: load a generated tag, conditional update succeeds, tag changes, stale
   update fails, deleted-record update fails, unconditional update still replaces the record.
3. Test batch rollback when one conditional record conflicts, and two independent store instances racing with
   the same tag: exactly one succeeds.
4. Test scope isolation for load/save/delete/clear, duplicate keys within a batch, empty operations and restart.
5. Round-trip a real persisted signal over a fresh graph; perform two flushes to cover the current unconditional
   session path. Exercise migrations, buster clearing and reserved keys through the shared suite.
6. Add a setup and round-trip docs page, including a conditional-save example and the session limitation above.
7. Run the full adapter suite against PostgreSQL in CI; an unavailable database must fail its integration job.
   Keep these tests out of Fable and NativeAOT core gates.

The local Docker client is installed but the Desktop engine was stopped during investigation. No PostgreSQL
integration test has run, and no adapter implementation is claimed complete.

## Remaining slices

- **Marten journal:** specify acknowledgement, bounded buffering, append identity, retries, ordering and stream
  ownership before connecting the synchronous `Record` hook to network IO. Snapshot position must never advance
  beyond durable journal entries. State and journal operations are not automatically one transaction.
- **KurrentDB:** use expected stream revisions for journal conflicts; define snapshot storage and stream lifecycle.
- **Equinox/FsCodec:** choose a real backend for the sample. Equinox is an abstraction over stores, and FsCodec
  handles event encoding; neither chooses the deployment database for the application.
- **Kafka:** begin with a journal sink keyed by graph stream. A compacted topic retains the latest keyed value,
  but does not directly supply `IStateStore`'s requested-key reads and per-record expected-version writes.
